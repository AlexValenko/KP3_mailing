# Сервис управления рассылками «Рассылка»

## Краткое описание

Данный проект представляет собой учебный прототип веб-приложения на Django для управления рассылками сообщений клиентам.
Пользователь создает получателей, сообщения и рассылки, запускает отправку писем вручную и просматривает статистику попыток.
Для менеджера предусмотрены просмотр рассылок и клиентов, отключение рассылок и блокировка пользователей.<br>
Зависимости проекта управляются через Poetry и указаны в pyproject.toml. Для хранения данных используется PostgreSQL,
для кеширования показателей главной страницы — Redis. Шаблоны оформлены с использованием Bootstrap.<br>

## Установка и использование

### Требования:
Python 3.14<br>
Poetry<br>
PostgreSQL<br>
Сервер Redis версии не ниже 8<br>
Почтовый аккаунт с доступом к SMTP для отправки писем<br>

### Установка проекта
Скачайте проект и перейдите в его корневую папку.<br>
Установите Poetry и зависимости:

```bash
pip install poetry
poetry install
```

Создайте базу данных PostgreSQL. В корне проекта создайте файл .env и заполните собственными значениями:

```dotenv
SECRET_KEY=секретный_ключ_Django
DEBUG=True
NAME=имя_базы_данных
USER=пользователь_базы_данных
PASSWORD=пароль_базы_данных
HOST=localhost
PORT=5432
EMAIL_HOST_USER=ваш_email
EMAIL_HOST_PASSWORD=пароль_приложения_для_почты
```

В config/settings.py настроен SMTP Gmail с TLS, порт 587. При использовании другого почтового сервиса измените настройки SMTP.<br>
Запустите PostgreSQL и Redis. Адрес Redis в текущих настройках: redis://127.0.0.1:6379/1.<br>
Примените миграции, создайте администратора и запустите сервер:

```bash
poetry run python manage.py migrate
poetry run python manage.py createsuperuser
poetry run python manage.py runserver
```

Главная страница: http://127.0.0.1:8000/home/<br>
Панель администратора: http://127.0.0.1:8000/admin/<br>

## Основной функционал

### Пользователь
- Регистрация по email с подтверждением адреса по ссылке из письма.
- Повторный запрос письма подтверждения, вход и выход из системы.
- Редактирование имени, фамилии, телефона и аватара. Изменение email через профиль отключено.
- Смена пароля и восстановление забытого пароля через письмо со ссылкой.
- Создание, просмотр, редактирование и удаление своих получателей, сообщений и рассылок.
- Выбор собственных сообщений и получателей при заполнении формы рассылки.
- Ручной запуск отправки со страницы подтверждения рассылки.
- Просмотр личной статистики: успешные и неуспешные попытки, количество отправленных писем и история с пагинацией.

### Менеджер
- Просмотр всех рассылок и получателей без редактирования и удаления чужих данных.
- Отключение и повторное включение рассылок.
- Просмотр списка пользователей и отдельных карточек, поиск по email.
- Блокировка и разблокировка пользователей. Блокировка своего аккаунта и суперпользователя запрещена.

Группа менеджеров создается в панели администратора. Ей назначаются разрешения:
`mailing.view_all_mailings`, `mailing.view_all_recipients`, `mailing.disable_mailing`,
`users.view_customuser`, `users.block_user`. Нужные пользователи добавляются в эту группу.<br>

### Ограничения доступа и отправки
Главная страница, регистрация, вход и страницы подтверждения и восстановления доступны без авторизации.
Для работы с личными данными требуется вход и подтвержденный email. Заблокированный пользователь не может войти.<br>
Подтверждение почты не снимает блокировку менеджера. Восстановление пароля не подтверждает email и не разблокирует аккаунт.<br>

Начало новой рассылки должно быть в будущем, окончание — позже начала. При редактировании разрешено оставить прежнюю дату начала.<br>
Отправка разрешена только владельцу рассылки, если она включена и текущее время находится между началом и окончанием включительно.
Без получателей отправка не выполняется. Автоматического запуска по расписанию нет.<br>

Статус определяется по датам: «Создана» — до начала, «Запущена» — в разрешенном периоде, «Завершена» — после окончания.
Статус «Запущена» не означает, что письма уже отправлялись. Повторный ручной запуск в разрешенном периоде отправит письма снова.<br>
Каждому получателю отправляется отдельное письмо. Результаты сохраняются в модели попыток пакетом через bulk_create().
Ошибка отправки одному получателю не останавливает остальные отправки. Количество отправленных писем равно количеству успешных попыток;
это результат работы почтового сервера, а не подтверждение прочтения письма.<br>
Email получателя уникален во всей базе, в том числе для разных владельцев.<br>

### Кеширование
Три показателя главной страницы — число рассылок, активных рассылок и получателей — сохраняются в Redis на 60 секунд.
Поэтому после изменения данных показатели могут обновиться с задержкой. При отсутствии записи в кеше выполняется новый подсчет.<br>
Для работы текущей конфигурации сервер Redis должен быть запущен. Используется Redis версии не ниже 8.<br>

## Примеры использования
1. Зарегистрируйтесь, откройте письмо и подтвердите email. При необходимости проверьте папку «Спам» или запросите письмо повторно.
2. Войдите на сайт, добавьте получателей и создайте сообщение с темой и текстом.
3. Создайте рассылку, выберите сообщение, получателей и период отправки.
4. В разрешенный период откройте детали рассылки, нажмите «Выполнить рассылку» и подтвердите отправку.
5. Результаты доступны в разделе статистики в меню «Профиль».

## Описание модулей
**Приложение mailing** — получатели, сообщения, рассылки, попытки отправки и главная страница.
Логика отправки писем находится в services.py, формы и проверки дат — в forms.py.<br>
**Приложение users** — модель пользователя, регистрация, подтверждение email, вход, профиль, пароли,
личная статистика и действия менеджера над аккаунтами. Проверка подтверждения почты вынесена в mixins.py.<br>
**Пакет config** — настройки проекта и основные маршруты.<br>

## Документация и ссылки
Настройки подключения к базе, почте и кешу находятся в config/settings.py; личные учетные данные хранятся в .env.<br>
Проект предназначен для учебного использования и локального запуска.<br>
